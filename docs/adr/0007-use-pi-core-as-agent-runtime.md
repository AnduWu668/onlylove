# 使用 Pi Core 作为 Agent 运行时

OnlyLove 的 MVP 使用 `pi-agent-core` 与 `pi-ai` 承载画像访谈、画像提取、恋爱分身和配对评估的 Agent 循环，但业务数据库继续拥有消息、画像和权限数据。Agent Engine 只向业务 Module 暴露 `continueInterview`、`extractPortrait`、`replyAsTwin` 和 `evaluatePair` 四个业务方法；每次请求临时创建 Agent、按角色恢复最小上下文并在写回结果后销毁。访谈员读取当前分身上下文、匹配档案和近期访谈，提取器读取当前画像与本次新增访谈，公开分身读取会话固定的分身上下文、允许公开的基础档案和当前会话，配对评估 Agent 只读取双方匹配档案与匹配规则；公开分身从数据层就不能取得隐藏标签、匹配分、内部提示或其他访客记录。单次输入使用可配置的应用级 token 预算，默认 32K，约 24K 时形成画像检查点；上线前用 16K、32K、64K 长对话基准决定正式配置。内部 Agent 定义记录角色、版本、Prompt 文件、允许的 Tool、输出 Schema、主模型与已通过同角色基准的备用模型，所有调用把画像与规则版本、供应商、请求及实际模型、输入输出 token、延迟、重试、切换、错误和估算成本落库。主模型在输出前失败或后台任务写入前失败时可以整体切换备用模型，但已经开始的流式输出不在中途换模型。MVP 初始使用火山方舟的一个固定主模型，最终模型仍由 Agent 基准决定。生产会话不加载 Pi Coding Agent 的文件、Shell、任意上传或动态 Skill 能力；Agent 基准必须包含套取隐藏画像、提示注入、冒充管理员和索取其他会话的用例。
